BASE DE DATOS DEL HOST - GUÍA GENERAL
=====================================

Esta guía es para cualquier host, aunque no sea técnico. No necesitas escribir
código: te explica QUÉ debe quedar armado y con QUÉ nombres. Para hacerlo, usa
un programa con ventanas (ver "Qué necesitas"). Si prefieres comandos, lee
base-de-datos-tecnico.txt.


¿PARA QUÉ SIRVE?
----------------
Aquí los jugadores registran los paquetes (peces) que van pescando. Como la
base de datos la creas y la controlas tú, puedes revisar al final qué capturó
cada jugador y a qué hora.


QUÉ NECESITAS
-------------
1. Un programa de base de datos instalado en tu equipo. Se recomienda MariaDB
   (libre y gratuito). MySQL también sirve.
2. Una herramienta con ventanas para crear las tablas sin escribir código.
   Por ejemplo: DBeaver, HeidiSQL o phpMyAdmin.
3. La lista de tus jugadores (con cuántos vas a jugar).


CÓMO DEBE QUEDAR AL FINAL
-------------------------
Al terminar la preparación debes tener esto:

  1. Una base de datos llamada:  michoacan

  2. Dentro de ella, una tabla por cada jugador, con estos nombres:

        capturas_jugador01
        capturas_jugador02
        capturas_jugador03
        ... (una por jugador)

  3. Todas las tablas son IDÉNTICAS, con estos campos:

        Campo                  Qué guarda                          Tipo
        ---------------------  ----------------------------------  -------------------
        id                     Número del registro (automático)    Número entero
        pez                    Nombre del pez capturado            Texto (hasta 50)
        protocolo              TCP, UDP, FTP...                    Texto (hasta 10)
        codificacion           UTF-8, Base64...                    Texto (hasta 20)
        mensaje_decodificado   El mensaje ya decodificado          Texto largo
        hora_registro          Fecha y hora del registro           Fecha y hora

     - "id" debe ser la llave principal y numerarse solo (autoincremento).
     - "hora_registro" debe llenarse sola con la hora actual del servidor.
     - Ningún campo es opcional, excepto id y hora_registro, que se llenan solos.

  4. Un usuario por jugador, con estos nombres:

        jugador01, jugador02, jugador03... (el mismo número que su tabla)

     Cada uno con su contraseña distinta.

Así se ve una tabla con un registro de ejemplo:

   id | pez              | protocolo | codificacion | mensaje_decodificado        | hora_registro
   ---+------------------+-----------+--------------+-----------------------------+--------------------
   1  | Kurucha urapiti  | TCP       | UTF-8        | Pescaste un Kurucha urapiti | 2026-11-24 20:35:10


PASOS GENERALES
---------------
1. Instala MariaDB y tu herramienta con ventanas.
2. Crea la base de datos "michoacan".
3. Crea UNA tabla "plantilla_capturas" con los campos de la tabla de arriba.
4. Copia esa tabla una vez por jugador, y ponle a cada copia su nombre
   (capturas_jugador01, capturas_jugador02...). Tu herramienta tiene la opción
   de duplicar una tabla.
5. Crea el usuario de cada jugador con su contraseña.
6. Dale a cada usuario los permisos que se indican abajo, solo sobre SU tabla.
7. Prueba con un jugador de práctica antes de empezar la partida.


PERMISOS QUE DEBE TENER CADA JUGADOR
------------------------------------
Sobre su propia tabla:
  - Puede VER sus registros.
  - Puede AGREGAR registros nuevos (pez, protocolo, codificación y mensaje).

No debe poder:
  - Modificar ni borrar registros.
  - Escribir la hora (la pone siempre el servidor).
  - Ver ni tocar las tablas de otros jugadores.
  - Crear ni borrar tablas o bases de datos.

Tú, como host, conservas todos los permisos.


¿UNA SOLA BASE DE DATOS O UNA POR JUGADOR?
------------------------------------------
Opción A (la más fácil): una sola base de datos "michoacan" con una tabla por
jugador. Recomendada para niñas, niños, estudiantes o grupos de nivel parecido.

Opción B (más aislada): una base de datos por jugador, llamadas
michoacan_jugador01, michoacan_jugador02... y dentro de cada una una tabla
llamada "capturas". Recomendada si hay jugadores muy hábiles o es una
competencia profesional, porque así no pueden ver nada de los demás.

En ambas, la tabla tiene los mismos campos de arriba.


SEGURIDAD: INDICACIONES GENERALES
---------------------------------
- Juega solo en una red acordada entre todos los participantes. No dejes la base
  de datos abierta a internet.
- Usa una contraseña distinta para cada jugador y anótalas aparte.
- Nunca le des a un jugador tu usuario de administrador.
- Dale a cada jugador solo el acceso a su propia tabla, nada más.
- Permite conexiones únicamente desde los equipos de la red del juego.
- Al terminar la partida, borra los usuarios de los jugadores para que no
  queden accesos abiertos.
- Guarda una copia de los registros si quieres conservar los resultados.


LISTA DE VERIFICACIÓN ANTES DE EMPEZAR
--------------------------------------
[ ] La base de datos se llama michoacan (o michoacan_jugadorNN si usas la opción B)
[ ] Hay una tabla por jugador, todas con los mismos campos
[ ] Cada jugador tiene su usuario y su contraseña distinta
[ ] Cada usuario solo puede ver y agregar en su propia tabla
[ ] La hora la pone el servidor
[ ] Probé con un jugador de práctica y funcionó
[ ] Entregué a cada jugador su usuario, su contraseña y el script pescador.py


PARA AUDITAR AL TERMINAR
------------------------
Abre la tabla de cada jugador con tu herramienta y ordénala por hora_registro.
Compara los peces, los protocolos y las horas con las reglas que dictaste, y
asigna los lugares. Si hay empate, se verá en los registros.


SI NO TE SIENTES CÓMODO
-----------------------
Pide ayuda a alguien con conocimientos de bases de datos, o usa la versión con
comandos (base-de-datos-tecnico.txt), donde puedes copiar y pegar cada paso.
